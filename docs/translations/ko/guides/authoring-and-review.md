# 에셋 리뷰와 개선

`.ashfox` 원본을 편집하고 다시 빌드한 뒤 생성 결과를 확인하세요. 에이전트가 편집과 명령을 수행할 수 있지만 컴파일 성공만으로 게임에서 보기 좋거나 소리가 적절하다는 것을 증명하지는 못합니다.

## 유용한 방향 제시하기

대상, 실루엣, 팔레트, 크기, 동작이나 사운드를 명시하세요. 기존 에셋을 바꿀 때는 보존할 내용을 알려줍니다. 예를 들면 다음과 같습니다.

```text
현재 표정과 눈 무늬는 유지하면서 그리핀의 머리를 더 넓게 만들어라.
모든 클립 이름을 보존하고 게임 번들을 다시 빌드해 바뀐 파일을 보고해라.
```

실제 원본 폴더와 의도한 출력 ID를 제공하세요. 명령 기반 작업 순서는 [에이전트 작업 흐름](agent-workflow.md)을 참고합니다.

## 종류별 리뷰

| 에셋 | 확인할 내용 |
| --- | --- |
| 모델 | 실루엣, 크기, 얼굴 방향, 재질, 텍스처 이음새, 부착 지점 |
| 애니메이션 | 모든 클립, 시작·종료 포즈, 극단 포즈, 부착물, 게임 타이밍 |
| 스프라이트 | 투명도, 16×16 가독성, 대비, 가장자리, 게임 필터링 |
| 사운드 | 모든 변형, 어택·릴리스, 클리핑, 다른 효과 대비 음량 |
| 번들 | 예상 ID·경로·선택 변형, 대상 엔진 임포트 설정 |

모델 시점, 동작 GIF, 원래 크기·확대 스프라이트, 사운드 파형에는 [CLI 관찰](observe.md)을 사용합니다. 청취용 WAV를 출력하세요. 캡처는 관찰 결과를 나타내며 게임 출력에는 에셋 자체가 들어 있습니다.

## 안전하게 반복하기

단일 에셋은 소스 편집 후 `inspect`, `capture` 또는 `replay`, export를 수행합니다. 설정된 전달물은 `check`, `build`, `verify` 후 새로 반환된 출력 디렉터리를 검사합니다. 실수로 이전 번들을 리뷰하지 마세요. 소스를 Git으로 관리해 의도적으로 비교·복원할 수 있게 합니다.

모델이 임포트 후에만 이상하면 소스 수정 전에 임포터의 축·크기·재질 설정을 확인하세요. 스프라이트가 흐리면 필터링을, 소리가 나지 않으면 런타임 이벤트·변형 경로와 재생 설정을 확인하세요. [문제 해결](troubleshooting.md)을 참고합니다.
