# 에셋 하나 검사하고 캡처하기

CLI를 헤드리스 에셋 작업대로 사용하세요. 모델·아이템·사운드·기존 PNG 하나를 불러와 검사하고 카메라나 애니메이션 포즈를 선택해 미디어를 메모리로 받습니다. 상위 `.ashfoxworkspace`는 무시하며 프로젝트 빌드, 출력 폴더 생성, 소스 변경을 수행하지 않습니다.

## 첫 캡처

[CLI 설치](install.md) 후 압축을 푼 스타터 폴더에서 실행합니다.

`capture`는 stdout에 PNG 바이트를, `inspect`는 JSON을 씁니다. 리다이렉션·파이프·프로세스 API로 결과를 받으세요. 브라우저 창을 직접 조작할 필요는 없습니다. 렌더링에는 Chrome·Chromium이 필요하며 표준 위치가 아니면 `ASHFOX_CHROME_PATH`를 설정합니다. 잘못된 경로를 명시하면 실패합니다. 컴파일·검사·일반 export에는 Chrome이 필요 없습니다.

렌더러는 Ashfox 공통 렌더링 라이브러리의 장면 투영, 카메라 프리셋, 재질 규칙, 애니메이션 샘플링을 사용합니다. 임시 프로필을 쓰는 비공개 헤드리스 프로세스를 시작하며 정상 정리 시 프로필을 제거합니다. 원본과 캡처 미디어는 메모리로 전달합니다. 호스트를 강제 종료하면 임시 프로필이 남을 수 있지만 에셋 디렉터리를 암묵적으로 만들지는 않습니다.

stdin 원본, 기존 PNG 바이트, 출력 처리, 지속 세션은 [Stdio와 메모리](stdio.md)를 참고하세요.

## 볼 내용 선택하기

반복 실행에는 새 파일명을 사용하세요. 실제 노드·텍스처·클립·변형 ID는 `inspect`로 찾으며 클립과 텍스처에는 이름도 허용합니다. 사운드 캡처는 피크 포락선 파형이며 재생 가능한 WAV는 `export`로 받습니다. 스프라이트 검사는 영수증과 픽셀별 소유권 증거를, 모델 검사는 노드·텍스처 메타데이터·애니메이션 채널·설정을 반환합니다. `inspect --node NODE_ID`는 정지 포즈 하위 트리 치수와 면·UV 검사를 추가합니다.

| 옵션 | 허용값과 동작 |
| --- | --- |
| `--camera` | 기본 `perspective`, `native`, `front`, `back`, `left`, `right`, `top`, `bottom`. 방향 프리셋은 작성한 forward를 따름 |
| `--azimuth`, `--elevation` | 도 단위 −360…360, −89…89. 모델 축 기준으로 0°는 음의 Z, +90°는 양의 X에서 바라봄. 고도는 XZ 평면 위 각도 |
| `--zoom` | 0.1…10, 기본 1. 1보다 크면 가까워지고 잘릴 수 있음 |
| `--width`, `--height` | 정수 16…2048, 모델·파형 기본 640×360 |
| `--environment` | `studio`, `day`, `evening`, `night` |
| `--background` | `environment`, `transparent`, `checker`, `light`, `dark`. PNG·스프라이트 기본은 투명 유지 |
| `--clip`, `--time` | 클립 ID·이름과 초. 0 아닌 시간에는 클립이 필요하고 클립 길이를 넘을 수 없음 |
| `--wireframe`, `--skeleton`, `--no-textures` | 모델 검사 오버레이와 중립 형상 |
| `--node` | 모델 노드 ID. 캡처는 하위 트리만, 검사는 치수 측정 |
| `--texture` | 모델 텍스처 아틀라스 하나를 PNG로 캡처 |
| `--scale` | 스프라이트·PNG·아틀라스 정수 1…32, nearest 확대, 최대 4096×4096 |
| `--stage` | 스프라이트의 `final`, `silhouette`, `shade`, `grain` |
| `--variant` | 사운드 변형 ID, 기본은 첫 컴파일 변형 |

궤도 옵션은 카메라 프리셋 방향보다 우선합니다. 둘 중 하나를 지정하면 생략한 방위각·고도의 기본값은 45°·20°입니다. 모델·파형 크기와 PNG 확대는 별도 제어입니다. 카메라 옵션은 원본 형상을 변환하지 않습니다.

## 동작 또는 빌드 리플레이 보기

{{source-code:2}}

동작·턴테이블 리플레이는 `--fps` 1…30(기본 10), `--duration` 0.01…30초, 카메라·캡처 크기를 받습니다. 동작의 기본 길이는 클립 길이이고 클립 없는 턴테이블은 3초입니다. `--time`에서 시작해 클립 끝에서 순환합니다. 프레이밍은 매 프레임을 쫓지 않고 샘플 포즈 전체에서 유지됩니다. 최대 300프레임·1억 렌더 픽셀이므로 넘으면 해상도·길이·프레임률을 줄이세요.

빌드 리플레이는 브라우저의 정식 재구성 방식으로 형상, 텍스처, 가능한 idle, 완성 순서를 보여줍니다. **편집 이력 녹화가 아닙니다.** 고정 640×360·10fps이며 브라우저의 perspective·native·front·left·right·top 프리셋과 환경을 지원합니다. 사용자 궤도·타이밍·오버레이·프레이밍 옵션은 거부합니다. 실제 작업 이력은 에이전트나 빌드 시스템에 리비전과 캡처를 보관하세요.

## 선택한 에셋 출력하기

{{source-code:3}}

기본값은 모델의 portable GLB, 스프라이트의 네이티브 PNG, 사운드의 WAV입니다. 모델 `--format`은 `glb`, `gltf`, `java_block`, `geckolib5`, `bedrock`을 받습니다. Minecraft 포맷에는 `--namespace`가 필요하며 `--model-path`로 기본 진입점 이름을 바꿉니다. 다중 파일은 ZIP, GLB는 원시 GLB로 반환합니다. 대상 준비·호환성 검사는 계속 적용됩니다. 보기 설정은 출력 에셋을 바꾸지 않습니다. 여러 에셋 게임 번들과 사운드 팩에는 [프로젝트 빌드](workspace.md)를 사용하세요.
