# 에셋 에이전트와 작업하기

에이전트에게 네이티브 원본 폴더와 CLI 접근을 제공하세요. 모델·스프라이트·사운드 작성, 전달 설정, 빌드 실행, 정확한 출력 보고를 수행할 수 있습니다. 파일 기반 파이프라인에는 브라우저 연결이 필요하지 않습니다.

## 작업 프롬프트

```text
선택한 .ashfox 원본과 가져오는 모듈을 읽고 관련 없는 에셋은 보존해라.
단일 에셋이면 검사 후 원본을 수정하고, 유용한 시점을 캡처하고 바뀐 동작을 재생해라.
메모리 출력에는 stdio를 쓰고 요청한 파일만 저장해라.
설정된 게임 전달 작업이면 워크스페이스의 check, build, verify도 실행해라.
관찰한 결과와 대상 게임에서 아직 확인해야 하는 내용을 보고해라.
```

대상, 크기, 팔레트, 동작·사운드 의도, 전달 위치를 추가하세요.

## 작업 순서

1. 단일 에셋 명령, 메모리 세션, 설정된 빌드 중 [실행 방식](choose-a-format.md)을 선택합니다.
2. 원본과 식별자를 검사합니다. 단일 에셋 관찰은 상위 워크스페이스를 무시하고, 프로젝트 빌드는 그 소스 선택 규칙을 따릅니다.
3. 원본을 편집하거나 `expectedRevision`으로 전체 세션 그래프를 교체합니다.
4. 검사하고 관련 시점·픽셀을 캡처하며 사운드 변형을 들어봅니다.
5. 선택한 에셋을 출력하거나 설정된 전달물에 check·build·verify를 실행합니다.
6. 미디어나 출력 위치를 반환하고, 관찰된 결과와 아직 검증하지 않은 대상 게임 동작을 구분합니다.

## 전달 방식

소스 선택과 출력 규칙은 [프로젝트 설정](workspace.md)을 사용합니다. 런타임 ID와 임포트 힌트는 [게임 에셋](game-assets.md), 아이템·사운드 이벤트 매핑은 [Minecraft 팩](minecraft-packs.md)을 사용하세요. 포맷을 명시적으로 설정하고 버전 이름으로 호환성을 추측하지 마세요.

소스 파일을 직접 편집하거나 stdio의 원본 교체 작업을 사용합니다. 프로젝트 `build`는 검증 후 완전한 출력을 발행합니다.

## 편집 중 관찰하기

편집 후 [단일 에셋 캡처](observe.md)로 ID, 관련 시점과 텍스처 상세를 확인하고 바뀐 동작마다 재생합니다. stdout에서 PNG·GIF 바이트를 읽거나 지속적인 `ashfox stdio` 세션을 사용하세요. 세션의 `load`는 예상 리비전과 함께 전체 원본 그래프를 교체하며, 컴파일 실패 시 이전 에셋을 보존합니다. 캡처에 워크스페이스 발행은 필요하지 않습니다.
