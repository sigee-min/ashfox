# Ashfox DSL 레퍼런스

Ashfox DSL은 모델·픽셀 텍스처·사운드·구조물의 원본 형식입니다. 이 레퍼런스는 통합 `ashfox 1` 언어를 설명합니다. 원본은 UTF-8 `.ashfox` 파일로 저장하세요. GLB·PNG·WAV·NBT·JSON은 출력물이므로 에셋을 바꾸려면 원본을 편집하고 버전 관리합니다.

## 소스 형태

모든 파일은 `ashfox 1` 헤더로 시작하고 최상위 단위 하나를 포함합니다. 헤더는 네 종류 에셋 모두의 통합 언어 버전을 식별합니다.

| 최상위 단위 | 의미 | 허용 내용 |
| --- | --- | --- |
| `model Name { … }` | 모델 진입점 | import, design, contract, skeleton, surface, component, motion, 조립(`settings`, `skeleton`, `motions`, `use`, `connect`) |
| `module Name { … }` | 재사용 모델 선언 | import와 공개·비공개 모델 선언 |
| `sprite name { … }` | 픽셀 스프라이트 하나 | import, 재사용 스프라이트 선언, profile, canvas, palette, layers |
| 스프라이트에서 쓰는 `module name { … }` | 재사용 스프라이트 선언 | import와 공개 mask·material·stamp |
| `sound name { … }` | 효과음 하나 | 오디오 속성, 공간, 보이스, 시퀀스, 변형, 루프·마스터링 설정 |
| `structure id { … }` | Minecraft·GLB 건축물 | 블록 상태 팔레트, 커스텀 `.ashfox` 소품, 프리팹, 지붕, 단면·실내 연산 |
| 구조물에서 쓰는 `module id { … }` | 재사용 실내 가구 | 선택적 팔레트와 `export prefab` 모듈 |

모델 진입점의 `model Name { … }` 블록은 선언과 함께 최상위 조립(`settings`, `skeleton`, `motions`, `use`, `connect`)을 직접 담습니다. 스프라이트·사운드·구조물도 바깥 단위 안에 속성을 직접 둡니다. 공용 `module` 선언은 도메인 문맥을 따르며 import가 모듈을 다른 종류의 에셋으로 변환하지 않습니다.

## 도메인 문법 요약

| 기능 | 모델 | 스프라이트 | 사운드 | 구조물 |
| --- | --- | --- | --- | --- |
| 산술과 타입이 있는 design | 지원 | 미지원 | 미지원 | 정수·블록 `params` 산술 |
| 숫자 표기 | `u`, `px`, `deg`, `s`, `%`/무차원 비율을 붙인 정확한 소수 | `px` 좌표·크기·반지름·축 및 무차원/`%` 제어 | `s`, `ms`, `hz`, `khz`, `db`, `lufs`, `cents`, `st`, `%` 단위, 범위 `a..b`, 전환 `a -> b` | `b` 블록 좌표·크기, `%` 또는 소수 가중치·비율 |
| 컬렉션 | 타입이 있는 튜플·벡터 `(a, b, c)` | 목록 `[a, b]` 및 `{ k = v; }` 블록 | `{ k = v; }` 블록과 점 목록 | `{ k = v; }` 블록과 대상 목록 |
| import | 명시적 별칭과 export 선언 | 스프라이트 선언의 상대 import | 모듈형 `sound` / `module` 선언 | 모델·프리팹용 상대/패키지 import |
| 주석 | `//`, `/* … */` | `//`, `/* … */` | `//`, `/* … */` | `//`, `/* … */` |

모델 표현식을 스프라이트·사운드·구조물 속성에 복사하지 마세요. 모델 `duration = 1s;`와 사운드 `duration = 1s;`는 모두 초를 쓰고 구조물 `size = (9b, 13b, 9b);`는 블록 단위(`b`)를 씁니다. 사용자 정의 함수, 반복문, 상속, 런타임 코드, 자동 부착 추론은 없습니다. 컴포넌트·모듈·명시적 import로 재사용하세요.

## 컴파일과 진단

독립 진입점은 명시적인 import 의존성을 컴파일합니다. 상위 워크스페이스가 있으면 설정이 선택과 출력 경로를 결정합니다. 파일명을 추측하지 말고 빌드 응답에서 출력 디렉터리를 확인하세요.

| 실패 | 확인할 내용 |
| --- | --- |
| 문법 오류 | 헤더, 감싸는 단위, 중괄호, 속성 철자, 세미콜론 |
| 알 수 없거나 비공개인 이름 | import 별칭, 선언의 export 여부, 정확한 이름 |
| 타입·단위 불일치 | 필드의 기대 타입과 모든 피연산자 접미사 |
| 차트 불일치·격자 밖 픽셀 | 형상 치수, 차트 전개도, 아틀라스 위치, 스탬프 범위 |
| 리그·소켓 불일치 | 명목적 계약 식별자, 완전한 바인딩, 명시적 연결 |
| 이름 있는 design 검사 실패 | 작성한 관계 자체. 검사가 형상을 고치지는 않음 |
| 미사용 코드·모듈 혼재 | 미사용 import·선언·스탬프 제거 및 관심사별 모듈 분리 |

진단은 소스 위치나 필드 포인터를 포함합니다. 후속 오류를 해석하기 전에 가장 이른 원본 오류를 고치세요. 컴파일 성공은 계약 검증이며 외형과 동작은 렌더링·재생으로 판단합니다.

이 레퍼런스의 `ashfox` 코드 블록은 완전한 실행 파일입니다. `text` 블록은 주변 계약이 필요한 조각이나 문법 개요입니다. 문서 테스트는 완전한 예제를 컴파일·빌드·검증합니다. CLI 실패는 [문제 해결](../guides/troubleshooting.md)을 참고하세요.
