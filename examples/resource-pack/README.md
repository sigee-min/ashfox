# Configurable resource pack

This example builds native sprites, a static block model and sound variants,
then maps their named exports into one Java resource-pack folder and ZIP.
The configuration is the authority for metadata, IDs and packaging:
[`.ashfoxworkspace`](.ashfoxworkspace).

```sh
npm run build:cli
node apps/cli/dist/ashfox.cjs build examples/resource-pack/.ashfoxworkspace --json
node apps/cli/dist/ashfox.cjs verify examples/resource-pack/dist/build --json
```

FFmpeg with `libvorbis` is required for the sound bindings. Put it on PATH or set
`ASHFOX_FFMPEG_PATH` to its executable. To build without audio, set the pack's
`sounds` to `[]`; original WAV exports still work without FFmpeg.

Use the returned `exports` entry named `game_pack`. Its `directory` contains
`resource-pack/` and `game_pack.zip`. The example replaces iron sword and stone
resources and also declares a `demo:rune_blade` item model and
`demo:combat.claw_hit` sound event. It does not install them or add new registered
items/blocks. The custom sound is not automatically bound to attacks.

Edit `items[].id`, `parent`, sound-event settings, selected variants, model export
namespace/modelPath, metadata format/range, and `archive` to suit the project.
`minecraftVersion` is a descriptive label; the explicit format fields determine
generated bytes. Older model semantics are not produced by changing that label.

See [the configuration and output contract](../../docs/guides/minecraft-packs.md).
